```sh
docker build -f scripts/model-eval/Dockerfile -t harbour-model-eval .
docker run --rm -it -v "$PWD:/workspace" harbour-model-eval
python3 scripts/evaluate-models.py \
  --models-directory /workspace/build/eval-models \
  --output-directory /workspace/build/eval-final \
  --efforts standard,quick,extended --repeats 3 \
  --context-checks --grammar-checks
python3 scripts/collect-model-evidence.py \
  --runs build/eval-final --output build/eval-final/run-manifest.json
python3 evaluation/score.py \
  --rows build/eval-final/small.jsonl build/eval-final/balanced.jsonl build/eval-final/qwen35.jsonl \
  --efforts standard,quick,extended --repeats 3 \
  --baseline build/eval-baseline/score.json \
  --run-manifest build/eval-final/run-manifest.json \
  --output build/eval-final/score.json \
  --review-queue build/eval-final/reviews.json
```

## Evidence and scoring

Standard runs every fixture. Quick and Extended run the fixtures explicitly marked `effortSubset`; only Standard's `timingSubset` receives repeated runs. Greedy repeats measure latency and determinism, rather than independent quality samples. Record cold load separately from warm requests, and retain failures and partial runs.

Cold load means the first actor request includes model loading. Hash verification may already have populated the operating system's file cache, so this is not an uncached disk-start benchmark. Warm requests retain the loaded model while the actor clears inference memory for each prompt. Current visit extraction uses one classification call and one extraction call for each selected source unit, with a 650-token maximum per call and a 4,096-token context. A fully executed chunk with N selected units requests up to 650 × (1 + N) output tokens across its calls; failure or cancellation may stop earlier. All actual call budgets and raw outputs are retained. This differs from the historical single-call 650-token visit path and is not an equal-total-compute comparison. Titles use 48 English/96 French tokens at every effort setting; routing and conversational budgets vary with effort.

Scoring distinguishes raw routing intent, the action accepted by production validation, ordinary reply quality, and raw visit extraction. A valid JSON envelope or a safely discarded proposal does not establish correct model output. The scorer checks expected source facts, selected medicines, schedule times, negated or quoted write requests, and both raw and accepted visit proposals. Language detection is only a lexical signal.

The [source-reading scope amendment](optional-model-source-reading-scope-v1.json) adds a bounded post-routing draft recovery for one complete, direct, unquoted, affirmative EN/FR recording request. Existing validation must establish the explicit supported type, value and compatible unit; it does not infer from model prose, history or saved data. The result opens the existing reading draft for user confirmation and performs no save. The full 21-tool catalog remains available to the model. Retain the raw route and suppressed prose beside the effective action, application origin and fallback reason; recovery earns no raw routing or model prose quality credit. This recorded application change leaves frozen fixture truth/digest, scorer and promotion thresholds unchanged.

The separate [source-symptom scope amendment](optional-model-source-symptom-scope-v1.json) supports a closed current first-person symptom report or recording request after routing. It copies the entire original text into the existing draft without deriving onset, severity or emergency signs. Existing manual sign selection, Review and Save remain required. Whole-source grammar excludes quoted, historical, negated, conditional, third-party, advice and compound reports. The raw route/output and application action/origin/reason remain separate; this recovery supplies no independent model-quality credit. Fresh source-bound correctness, xtool and full native checks are required before the final DEV phase.

The upstream appointment merge adds `create_appointment` and `list_appointments`, making the current catalog 21 rather than the baseline's 19. All 21 remain routing alternatives; frozen v1 still tests the original 19 intents and does not measure the two added appointment intents or appointment recall. As an explicit production-schema adaptation, the scorer accepts either the legacy three visit fields or those fields plus an appointments array of strict source-quote objects. It checks every raw/accepted appointment quote and reports raw, accepted, and fallback counts without treating source fallback as model recall. Original medicine and follow-up requirements and the fixture SHA remain unchanged. Paired results therefore include the changed catalog, prompts, context, grammar, and validation; they do not isolate architecture or unrestricted model intelligence. In the historical single-call visit path, for a single unambiguous current catalog instruction the app can construct a source-verbatim proposal and validate its identity, dose directions and schedule before generation. Only that narrow branch requires an entry and constrains its copied name and instructions to exact transcript literals; optional or uncertain branches retain their existing field rules. These deterministically constrained fields measure app pipeline behavior, not independent model extraction or general intelligence. The model still generates the other summary categories, and final source validation remains mandatory; no parsed medicine fallback is inserted.

That historical single-call path constrains medicine quotes and action alternatives to supported instructions in the transcript. All models use the same constraints. Outside the prevalidated single-entry branch, models select entries and generate names and directions; within it, exact source literals constrain those fields. Production validation checks the emitted proposals again. Missing changes and unsupported generated fields remain quality failures. These results compare the complete app behavior, rather than unconstrained model intelligence.

The current [staged visit protocol](harbour-quality-v2-staged-extraction-amendment.json) classifies every ordered source unit, then independently extracts selected units from their source and context. All 32 valid category sets remain selectable; duplicate categories and `none` mixed with another category cannot be decoded. Classifier labels select units but do not appear in extractor prompts. Extractor medicine and quote fields remain free model choices within the four-array output grammar; the source-constrained minimum-medicine grammar above is not used by this path. Unit-quote ownership and final whole-source validation filter proposals before application assembly. Every classifier/extractor output, including rejected proposals, remains in the trace. Review all raw stages separately from assembled output, accepted summaries and source-literal recovery; assembly or recovery earns no raw model recall. `--single-visit` retains the legacy path for explicitly labelled diagnostics.

Review every required open-ended answer for relevance, factual grounding, language, and extraction fidelity. Each review records the reviewer, decision, explanation, suite digest, and exact output digest. The recorded Codex reviews are qualitative AI review, not human clinician labels. Re-run the scorer with `--manual-reviews` after filling the queue; pending reviews block the gate. Preserve the queue and reviewed decisions with the raw evidence.

The historical v1 review procedure permits adjudicating only a `required_fact_missing` lexical match when the answer faithfully states the expected fact in different words. The decision must identify that failure, criterion, and supporting answer text. Preserve the original automatic result beside the adjudicated result. Routing, unsafe actions, extraction fields, bounds, and unsupported numeric facts cannot be overridden this way.

The frozen v2 rubric permits no lexical adjudications or post-output threshold changes. It requires explicit raw and accepted source/safety assessments, all visit-stage reviews, and separate accepted-action/summary safety checks even when the automatic unsafe flag is zero. Preserved original reviews and narrowly documented consistency corrections remain available beside derived comparisons.

It preserves all wording, internal decimals, dose, frequency, clock times, negation and source anchoring; it does not normalize question marks, exclamation marks, ellipses, empty directions or stop instructions. Original raw outputs and pre-correction verdict artifacts remain available, and this changes neither fixture truth/digest nor a quality threshold. This comparator correction is separate from manual lexical adjudication.
