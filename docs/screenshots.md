# Screenshots

## What it is

[The screenshot gallery](screenshots/index.html) contains genuine captures of the installed SwiftUI app on the Harbour QA iPhone simulator. Records shown are fictional test inputs. Each original PNG is available separately and the overview sheets provide a quick review.

## How it works

`HarbourCareFeatureTests` exercises real label OCR, schedules, dose logging, reminders, history search, appointment-question persistence, and matching local-model chat tools. `HarbourPermissionFeatureTests` checks notification enablement and voice availability. `HarbourStableMainScreensTests` waits for settled main destinations and checks dock reachability before capture. `HarbourAppearanceTests` exercises Light/Dark persistence and unchanged topic drafts; `HarbourRichResultsTests` exercises real local-model tool results; `HarbourDetailRefreshTests` covers the entry/review sheets. `HarbourDashboardTests` captures the equal-sized shortcuts, icon dock, and actual generated title. `HarbourFloatingDockTests` verifies scrolling/keyboard clearance and captures the overlay in use. `HarbourLockTests` captures four-slot PIN setup, unlock, mismatch, current-PIN verification, and retry delay. `HarbourFreshScreensTests` uses a separate fresh simulator for genuine download progress, unavailable Face ID, Apple Health permissions/status, and the file picker. `HarbourEvaluationScreenTests` captures a completed selected-model evaluation. These XCTest flows navigate the native app and save numbered XCTest screenshot attachments.

`scripts/export-screenshots.py` exports attachments from Xcode result bundles, preserves their device/test/timestamp provenance in `screenshots/manifest.json`, and generates a local HTML viewer. Image URLs include their file modification timestamp so a refreshed capture replaces browser-cached thumbnails and enlarged images; download filenames remain unchanged. Paired light/dark dashboard, chat, records, settings, model controls, and entry-sheet captures show the current appearance. `preview.jpg` uses light/dark dashboard, Records browser, and empty chat captures. Images are not mockups or generated designs.

The corner/icon refresh in `harbour-uniform-corners.xcresult` replaces the main pages and paired drawer-flow captures. Its Appearance, Models, PIN, Today, and dark Chat originals were visually inspected. Other images remain historical captures, with their original producing bundle recorded in the manifest.

Canadian French captures 117–137 cover all four destinations in Light/Dark and the settings, PIN, catalog, decimal-comma reading, symptom, topic, model, visit-note, reminder, and appointment-preparation drafts. `HarbourFrenchScreensTests` supplies those flows. `HarbourFrenchModelTests` supplies 138–141 from actual cached-model requests, including a generated French title and cancelled write reviews. English main-page captures come from `HarbourStableMainScreensTests`. Each image retains its producing-run provenance; older permission, download, and exceptional-state captures are historical.

The light-dock refresh replaces all eight English main-page captures. The focused medicine drawer flow replaces 7, 50, and 71 and adds 142 for dark visit medicine review; the last two show the current shared 54-point corner radius instead of the older visit-review presentation.

Its All screens section also embeds every numbered PNG, grouped by feature in two-column tables. It embeds the original PNGs at 220 pixels wide with descriptive alt text and links to their full-resolution files. Update those relative image paths when replacing the featured captures; keep the originals in `docs/screenshots/` so they render directly on GitHub without a running gallery server.

Pass `--update-readme` when exporting into the repository screenshot directory to refresh the complete README gallery between its generated markers. It uses the same captions and actual PNG inventory as the local gallery. Exports to a temporary `--output` directory cannot update the README. New capture numbers without a configured group appear under Additional screens, so they are included immediately; extend the group mapping in the export script when assigning them a feature section.

Add a numbered capture to the UI screenshot flow and its title to `TITLES` in the export script. Wait for the destination screen and its transitions to settle before capturing. Pass multiple result bundles to combine flows; a later capture with the same name replaces the earlier version. Inspect the actual PNGs after export, especially keyboards, long forms, share sheets, and download progress. Historical raw result bundles may be pruned after export; the PNGs, manifest provenance, and recorded outcomes remain. Reproduce them with the named test classes rather than assuming a temporary bundle still exists.

## Configuration

```sh
python3 scripts/export-screenshots.py --update-readme /tmp/harbour-dashboard-final.xcresult /tmp/harbour-chat-final.xcresult /tmp/harbour-fresh-final.xcresult /tmp/harbour-four-digit-pin.xcresult /tmp/harbour-layout-final.xcresult /tmp/harbour-system-final.xcresult
python3 scripts/export-screenshots.py /tmp/harbour-white-corrected.xcresult /tmp/harbour-white-final.xcresult /tmp/harbour-floating-dock.xcresult /tmp/harbour-floating-clearance.xcresult /tmp/harbour-inline-workflows.xcresult
python3 -m http.server 8765 --bind 127.0.0.1 --directory docs/screenshots
```

The localhost viewer is accessible only on the development computer. For remote/mobile review, embed the exported PNGs directly in the conversation using absolute filesystem paths; include each page rather than relying on a localhost link. Open `http://127.0.0.1:8765/` for local review. The viewer supports left/right keys and Escape. `--output` changes the export directory. Result bundles must come from the current native build when replacing updated screens; the directory path is not proof that the capture test passed. The main multi-flow capture was interrupted during the animation wait; its completed appearance, entry, and navigation flows passed. Later finished runs replace its chat captures. The four-digit run's PIN flow passed; its dashboard margin assertion was corrected in the subsequent dashboard run because decorative accessibility bounds include intentionally cropped artwork. Keep these boundaries distinct from the actual captures.

To repeat `HarbourFreshScreensTests`, create and boot a disposable iPhone simulator, then use its UUID as the Xcode destination. Do not reset an existing user's permissions or remove their downloaded models for screenshots. After exporting its attachments, shut down and delete that fixture simulator.

The white-palette refresh replaces dashboard, record categories/lists, entry/review, settings, composer, PIN, and rich chat captures. ## Dependencies

Xcode's `xcresulttool`, Python 3, and actual XCTest screenshot attachments. Pillow is optional for overview sheets. The viewer uses local HTML, CSS, and JavaScript without external dependencies.
